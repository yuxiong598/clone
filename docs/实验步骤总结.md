在 MetaMask 添加第 1 节的网络，切换到 POTOS Testnet，再通过网页右上角连接钱包。

## 3 完成两笔订单的三人实验

本合约已有历史订单。新订单以下用 N 和 N+1 表示，实验时记录页面真实 id。每次操作后等待交易成功，再观察状态和余额。

### 步骤四 买家创建第一笔订单

A 连接页面，卖家填 B 的地址，金额填 30，期限填 30 分钟，描述填“课程教材订单一”，点击创建订单并在钱包确认。列表出现订单 N，状态为 Created 待付款；A 看见付款按钮。

### 步骤五 买家一键授权并付款

A 点击“付款（授权 → 托管）”。第一次钱包请求是 Token 的 approve，spender 应为本次 Escrow 地址；授权成功后，第二次请求是 Escrow 的 deposit。两笔均确认后，订单变为 Paid 已托管，A 的代币余额减少 30。分别保存两笔交易哈希。

### 步骤六 对照买卖双方按钮

A 在 Paid 订单上可以看到确认收货、发起争议和超期退款；B 打开同一订单，只能看到发起争议。截图中应同时保留顶部当前地址和角色提示。此时先不确认第一笔订单。

### 步骤七 创建并支付第二笔订单

A 按相同方法创建“课程教材订单二”，金额仍为 30，完成 approve 和 deposit。记录第二笔真实 id N+1，确认状态为 Paid。

### 步骤八 卖家发起争议

B 对 N+1 点击发起争议并确认交易。状态变为 Disputed 争议中，A、B 均不显示仲裁按钮。保留争议交易哈希。

### 步骤九 仲裁人退款

C 连接页面，核对当前地址与仲裁人一致。N+1 应显示“判给卖家”和“退给买家”。点击退给买家并确认后，状态变为 Refunded 已退款，A 收回 30 个代币。

### 步骤十 买家确认第一笔订单

A 回到订单 N，点击确认收货并确认交易。状态变为 Completed 已完成，B 收到 30 个代币。不要对已完成或已退款订单重复操作。

最终两笔订单应分别为 Completed 和 Refunded。仅计算上述两笔业务且没有其他转账时，A 相比实验开始净减少 30 个代币，B 净增加 30；POT 余额还会因 gas 支出发生变化。

## 4 对照代码理解创建与付款

本节路径均相对于作业副本根目录。详细实现以实际源文件为准，以下仅摘录关键调用。

### 创建订单的代码

文件 packages/nextjs/utils/escrow.ts 中的 orderInput 检查地址、金额、期限和描述；parseUnits 按链上 decimals 换算金额，避免直接用浮点数乘精度。

文件 packages/nextjs/app/escrow/page.tsx 中的 create 使用最新区块时间计算截止时间：

```typescript
const block = await client.getBlock();
await escrowWrite("createOrder", {
  functionName: "createOrder",
  args: [input.seller, token.address, input.amount,
    block.timestamp + input.duration, input.description],
});
```

### 授权与付款的代码

同文件的 action 在 deposit 分支先读取订单与余额，再发 approve。以下为省略错误处理后的调用顺序：

```typescript
const hash = await wallet.writeContract({
  address: order.token,
  abi: erc20Abi,
  functionName: "approve",
  args: [contract.address, order.amount],
  account: signer,
  chain: targetNetwork,
});
const receipt = await client.waitForTransactionReceipt({ hash });
// 检查 receipt.status、当前账户及网络后继续
await escrowWrite(`deposit 订单 ${id}`, {
  functionName: "deposit", args: [id],
}, signer);
```

一次按钮点击仍对应两笔链上交易。若只授权成功就关闭页面，订单仍为 Created，代币仍在买家账户，但 allowance 已生效。可重新付款或在 Token 中将授权额设为 0。

### 角色和权限的代码

OrderCard 根据当前地址、order.buyer、order.seller、arbiter 和 order.status 显示按钮。Escrow.sol 中的 onlyBuyer、onlyArbiter 和 inStatus 在链上再次校验；修改前端或直接使用 Remix 不能绕过这些权限。

## 5 检查时间线与运行测试

### 步骤十一 展开订单时间线

对 N 和 N+1 分别展开时间线。正常结算应为“创建 → 付款 → 确认收货”；争议退款应为“创建 → 付款 → 争议 → 仲裁完成”。点击交易链接检查浏览器中的成功状态、From 和代币转账。

事件索引由 packages/nextjs/hooks/useEscrowIndex.ts 实现，从部署区块开始查询。每次最多查询 10 个区块，包含首尾区块，因此结束区块是 cursor + 9：

```typescript
const end = cursor + 9n < head ? cursor + 9n : head;
const logs = await client.getLogs({
  address: contract.address, events: eventAbis,
  fromBlock: cursor, toBlock: end,
});
cursor = end + 1n;
```

代码按区块号和日志序号排序事件，使用 OrderCreated 找到订单 id，再通过 getOrder 读取当前状态。approve 属于 Token 合约，不在 Escrow 时间线中；请从会话记录、钱包或区块浏览器保存其哈希。

### 步骤十二 执行自动检查

## 6 部署方式与提交仓库

### 默认方式 复用测试链合约

路线 B 默认使用已部署的 Escrow 与 YRHToken。运行 yarn start 即可演示。需要生产模式时执行：

```bash

yarn next:serve
```

如需远程发布，可使用项目自带的 yarn vercel:login 和 yarn vercel，先确认账号及目标项目；远程前端仍由用户自己的 MetaMask 签名，不能上传钱包私钥。

### 可选方式 本地链练习

三个终端均进入副本目录，依次执行：

```bash
# 终端一  保持运行
yarn chain
# 终端二  部署本地合约
yarn deploy --network localhost --tags Token,Escrow
# 终端三  启动本地链前端
NEXT_PUBLIC_LOCAL_CHAIN=true yarn start
```

MetaMask 使用本地 RPC http://127.0.0.1:8545，Chain ID 31337。本地默认部署者为仲裁人；为买家 mint 后走同样的业务流程。本地练习不能代替测试链验收。切回测试链时移除本地开关并重启前端。

若原仲裁人账户无法使用，组长可选择重新部署测试网合约：复制 packages/hardhat/.env.example 为 .env，在本地填 DEPLOYER_PRIVATE_KEY 和 ARBITER_ADDRESS，再执行 yarn deploy --network potos_testnet --tags Escrow。新部署会生成新地址与订单空间，组内必须统一更新；只有需要新 Token 时才使用 --tags Token,Escrow。

### 常见问题的处理

| 现象 | 检查方法 |
| --- | --- |
| 页面没有订单 | 检查网络、合约地址、部署区块；等待事件索引数量与 orderCount 一致 |
| 付款余额不足 | 分别检查 POT gas 余额与 YRHToken 余额，确认 mint 或转账已完成 |
| 只有一次钱包请求 | 第二笔要等授权成功；检查是否拒绝了 deposit，不要切换钱包账户 |
| 看不到仲裁按钮 | 当前地址须等于 arbiter，订单须为 Disputed |
| 超期退款失败 | 合约要求区块时间严格大于 deadline，且订单仍为 Paid |
| 模块缺失或启动很慢 | 重新完成 yarn install；WSL 中使用 Linux Node，避免混用 Windows 依赖 |
